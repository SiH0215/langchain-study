# 기초 완료 체크리스트

직접 실행하고 설명할 수 있을 때 체크한다. 예제나 문서가 추가됐다는 이유로 완료 표시하지 않는다.

## 개념과 입출력

- [ ] 모델 API와 LangChain 역할을 구분한다.
- [ ] 가상환경 Python과 설치 위치를 확인한다.
- [ ] 키를 코드에 넣지 않고 .env에서 읽는다.
- [ ] System/Human/AI/Tool 메시지 역할을 설명한다.
- [ ] API 호출 전에 템플릿의 최종 메시지를 출력한다.
- [ ] LCEL 각 단계의 입력·출력 타입을 설명한다.
- [ ] RunnableLambda/Parallel의 API 없는 예제를 실행한다.
- [ ] invoke/stream/batch/ainvoke 결과를 비교한다.
- [ ] Pydantic 구조화 출력과 사실 검증의 차이를 설명한다.

## 대화와 검색

- [ ] 대화 저장 후 재실행하여 이전 발언을 참조한다.
- [ ] 초기화 후 이전 기록을 참조하지 않는지 확인한다.
- [ ] 최근 문답 수 제한과 토큰 제한의 차이를 설명한다.
- [ ] Document의 원문과 metadata를 확인한다.
- [ ] 청크 크기·겹침을 바꿔 실제 경계를 출력한다.
- [ ] 임베딩 모델과 답변 모델의 역할을 구분한다.
- [ ] 검색 결과 원문·점수와 Retriever 출력을 확인한다.
- [ ] k=1/2/3으로 정답 포함과 잡음을 비교한다.
- [ ] 기본 RAG와 history-aware의 후속 질문 검색어를 비교한다.
- [ ] 문서에 없는 질문에서 추측하는지 확인한다.
- [ ] 인용 번호와 실제 원문이 일치하는지 확인한다.

## 도구와 점검

- [ ] Tool의 타입 힌트·설명과 입력 스키마 관계를 설명한다.
- [ ] tool_calls 요청과 ToolMessage 실행 결과를 구분한다.
- [ ] 곱셈이 실제 도구로 계산되고 결과가 391인지 확인한다.
- [ ] 같은 thread_id에서 후속 대화가 이어짐을 확인한다.
- [ ] timeout·재시도·429 오류 대응 방법을 설명한다.
- [ ] 질문 세트에서 검색 실패와 생성 실패를 나눠 기록한다.
- [ ] API 호출 횟수·토큰·경과 시간을 관찰한다.

## 비교 실험 순서

1. `basics --mode offline`으로 변수·메시지·Runnable을 확인한다.
2. 기본 호출을 실행하고 stream·batch·async와 비교한다.
3. chat에서 이름을 말하고 재실행·초기화 전후를 비교한다.
4. RAG 검색 전용 모드로 원문과 k 변화부터 확인한다.
5. 기본 RAG와 history-aware에 같은 두 질문을 순서대로 넣는다.
6. 없는 정보(예: 스터디 참가비)를 물어보고 답변과 근거를 대조한다.
7. Agent의 곱셈 요청·도구 결과·후속 대화를 확인한다.

## 설명 연습

- 대화 기록을 저장했는데도 왜 모델은 이전 대화를 모를 수 있을까?
- 검색 결과가 두 개 나왔는데 왜 답이 없을 수 있을까?
- 유사도 0.9가 정답 확률 90%를 뜻하지 않는 이유는?
- 재작성된 검색 질문과 원래 질문을 각각 어디에 쓰는가?
- 고정 RAG와 Agent를 선택하는 기준은?

이 항목을 직접 설명하고 작은 프로그램을 수정할 수 있으면 기초 사용 경험을 정리하기에 충분한 출발점이다.
실습하지 않은 PDF·DB 영속화·배포까지 구현했다고 표현하지 않는다.
