# 기초 완료 체크리스트

직접 실행하고 설명 가능한 시점에 체크. 예제나 문서가 추가됐다는 이유로 완료 표시하지 않음.

## 개념과 입출력

- [ ] 모델 API와 LangChain 역할 구분.
- [ ] 가상환경 Python과 설치 위치 확인.
- [ ] 키의 코드 하드코딩 대신 .env에서 읽기.
- [ ] System/Human/AI/Tool 메시지 역할 설명.
- [ ] API 호출 전에 템플릿의 최종 메시지 출력.
- [ ] LCEL 각 단계의 입력·출력 타입 설명.
- [ ] RunnableLambda/Parallel의 API 없는 예제 실행.
- [ ] invoke/stream/batch/ainvoke 결과 비교.
- [ ] Pydantic 구조화 출력과 사실 검증의 차이 설명.

## 대화와 검색

- [ ] 대화 저장·재실행 후 이전 발언 참조.
- [ ] 초기화 후 이전 기록을 참조하지 않는지 확인.
- [ ] 최근 문답 수 제한과 토큰 제한의 차이 설명.
- [ ] Document의 원문과 metadata 확인.
- [ ] 청크 크기·겹침을 바꿔 실제 경계 출력.
- [ ] 임베딩 모델과 답변 모델의 역할 구분.
- [ ] 검색 결과 원문·점수와 Retriever 출력 확인.
- [ ] k=1/2/3으로 정답 포함과 잡음 비교.
- [ ] 기본 RAG와 history-aware의 후속 질문 검색어 비교.
- [ ] 문서에 없는 질문에서 추측하는지 확인.
- [ ] 인용 번호와 실제 원문이 일치하는지 확인.

## 도구와 점검

- [ ] Tool의 타입 힌트·설명과 입력 스키마 관계 설명.
- [ ] tool_calls 요청과 ToolMessage 실행 결과 구분.
- [ ] 곱셈이 실제 도구로 계산되고 결과가 391인지 확인.
- [ ] 같은 thread_id에서 후속 대화가 이어짐 확인.
- [ ] timeout·재시도·429 오류 대응 방법 설명.
- [ ] 질문 세트에서 검색 실패와 생성 실패를 나눠 기록.
- [ ] API 호출 횟수·토큰·경과 시간 관찰.

## 비교 실험 순서

1. `basics --mode offline`으로 변수·메시지·Runnable 확인.
2. 기본 호출을 실행하고 stream·batch·async와 비교.
3. chat에서 이름을 말하고 재실행·초기화 전후 비교.
4. RAG 검색 전용 모드로 원문과 k 변화부터 확인.
5. 기본 RAG와 history-aware에 같은 두 질문을 순서대로 입력.
6. 없는 정보(예: 스터디 참가비)를 물어보고 답변과 근거 대조.
7. Agent의 곱셈 요청·도구 결과·후속 대화 확인.

## 설명 연습

- 대화 기록 저장 후에도 이전 맥락이 전달되지 않는 이유
- 검색 결과가 있어도 정답이 없을 수 있는 이유
- 유사도 0.9와 정답 확률 90%의 차이
- 재작성된 검색 질문과 원래 질문의 사용 위치
- 고정 RAG와 Agent의 선택 기준

이 항목을 직접 설명하고 작은 프로그램을 수정할 수 있으면 기초 사용 경험을 정리하기에 충분한 출발점.
실습하지 않은 PDF·DB 영속화·배포까지 구현했다고 표현하지 않음.
